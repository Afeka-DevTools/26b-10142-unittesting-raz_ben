# LEARNING - תיעוד שיחות חלק 2

קובץ זה הוא תיעוד השיחה הרלוונטית לחלק הלמידה של תרגיל בית 2. הוא נשמר
ב-`logs/` כנדרש במטלה; עותק תואם נמצא גם ב-[`chats/LEARNING.md`](../chats/LEARNING.md).
הכלי ששימש ללמידה היה Codex (LLM). ההמלצות נבדקו מול קוד הפרויקט ולא התקבלו
כערובה לנכונות ללא בדיקה.

## הקשר שניתן לכלי

- פרויקט Java 21 הבנוי בעזרת Gradle Wrapper.
- בדיקות JUnit 5 עבור הפונקציות הציבוריות של `app/src/main/java/org/example/App.java`.
- מטרת המטלה: להבין כיצד מתכננים בדיקות יחידה ולא רק לייצר בדיקות שעוברות.

## בקשה ראשונה

> הסבר בקצרה ובמבנה של נקודות מהי בדיקת יחידה ב-Java, כיצד משתמשים ב-JUnit 5,
> ואיך בוחרים מקרי בדיקה לפונקציה. תן דוגמאות לפונקציה שמחשבת עצרת ולפונקציה
> שבודקת ראשוניות.

## תשובה ותובנות שנלמדו

1. בדיקת יחידה בודקת יחידת קוד קטנה ומבודדת מול תוצאה צפויה. הבדיקה צריכה
   להיות דטרמיניסטית, קצרה ובלתי תלויה בסדר ההרצה של בדיקות אחרות.
2. ב-JUnit 5 מסמנים מתודת בדיקה ב-`@Test`. משתמשים ב-`assertEquals` להשוואת
   תוצאות, ב-`assertTrue`/`assertFalse` לתנאים בוליאניים, וב-`assertThrows`
   כאשר החוזה מגדיר חריגה.
3. בוחרים מקרי בדיקה מתוך מחלקות שקילות: קלט תקין טיפוסי, קלט גבול, וקלט לא
   תקין. עבור `factorial` נבדקו `0`, `1`, ערך חיובי, וערך שלילי שמעלה חריגה.
   עבור `isPrime` נבדקו ערכים שליליים, `0`, `1`, `2`, מספר ראשוני ומספר מורכב.
4. ערכי גבול חשובים מפני שטעויות נפוצות נמצאות סביב תנאי `if` ולולאות: לדוגמה
   האם הלולאה של עצרת מתחילה ב-2, והאם 2 מזוהה כמספר ראשוני.

## בקשת המשך

> איך יודעים שהבדיקות מספקות? הסבר את ההבדל בין כיסוי שורות לכיסוי ענפים,
> והצע דרך לאמת זאת בפרויקט Gradle.

## תשובה ותובנות שנלמדו

1. כיסוי שורות מודד אילו שורות קוד הופעלו לפחות פעם אחת. הוא אינו מוכיח שכל
   החלטה נבדקה בשני הכיוונים.
2. כיסוי ענפים מודד את שני הצדדים של תנאי: לדוגמה גם `n < 0` וגם `n >= 0`, או
   גם כניסה ללולאה וגם אי-כניסה אליה.
3. כיסוי של 100% הוא בדיקת בטיחות שימושית, אך אינו מחליף ציפיות נכונות. לכן
   הבדיקות כוללות גם ערכים צפויים מדויקים, מקרי קצה וחריגות.
4. בפרויקט Gradle נוסף JaCoCo. הפקודה `./gradlew clean check` מפעילה את JUnit,
   מפיקה דוח כיסוי, ונכשלת אם כיסוי השורות או הענפים של `App.java` נמוך מ-100%.

## יישום בפרויקט ואימות

התובנות יושמו ב-`AppTest.java`: יש בדיקות רגילות, בדיקות קצה, חריגות,
רישיות/רווחים/פיסוק במחרוזות, וסדר תוצאות ברשימות. בסיום הורצה הפקודה:

```bash
./gradlew clean check
```

היא הסתיימה בהצלחה, ודוח JaCoCo מציג 46 מתוך 46 שורות ו-26 מתוך 26 ענפים
מכוסים עבור `App.java`.
